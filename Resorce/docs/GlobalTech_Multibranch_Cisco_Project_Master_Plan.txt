DOCUMENT PURPOSE
----------------
This document is the corrected master plan for a Computer Networks course
project. It is designed for Cisco Packet Tracer and targets a realistic,
secure, redundant, scalable and cost-conscious enterprise network.

PROJECT TITLE
-------------
"Secure Multi-Branch Enterprise Network with Redundant WAN, Centralized
Services, Secure File Sharing and Fault-Tolerant Communication"

COMPANY MODEL
-------------
Company: GlobalTech Industries Ltd.

Network size:
- 1 Head Office (HQ)
- 20 regional branches
- At least 100 branch computers
- 5 PCs per branch = 100 branch PCs
- 15 additional HQ PCs
- Total planned user PCs = 115
- Central server room at HQ
- Central Network Security & Operations Center (NOC/Security Department)

PRIMARY PROJECT OBJECTIVES
--------------------------
1. Connect 20 branches through a WAN.
2. Provide communication between computers in different branches.
3. Provide centralized internal services from HQ.
4. Provide DHCP and DNS.
5. Provide internal web service.
6. Provide authenticated file transfer/download.
7. Provide SMTP/POP3 email communication.
8. Provide controlled Internet access using NAT/PAT.
9. Provide secure network administration using SSH.
10. Segment departments using VLANs.
11. Control traffic using ACLs.
12. Provide gateway redundancy using HSRP.
13. Provide dynamic routing using OSPF.
14. Provide redundant WAN connectivity where practical.
15. Demonstrate encrypted WAN communication using IPSec on supported
    representative links.
16. Make faults easy to locate and repair.
17. Demonstrate failure recovery during the final presentation.
18. Keep the design scalable and cost-conscious.

IMPORTANT DESIGN CORRECTIONS FROM THE PREVIOUS PLAN
----------------------------------------------------
Correction 1 – HSRP placement:
HSRP is primarily a first-hop/default-gateway redundancy mechanism for
hosts on a LAN. It should NOT be described as the main WAN redundancy
protocol. In this project, HSRP will be implemented on the HQ Layer-3
core/distribution gateway pair. WAN redundancy will be handled by
redundant paths and dynamic routing (OSPF), where the Packet Tracer
topology supports it.

Correction 2 – WAN edge redundancy:
HQ-R1 and HQ-R2 can both provide WAN/Internet connectivity, but their
redundancy is logically separate from HSRP. OSPF will determine routing
and can use an alternate path when a primary path fails.

Correction 3 – "Internal Internet":
The project will distinguish between:
A. Corporate internal services:
   DNS, DHCP, FTP, Mail, HTTP, NTP, monitoring.
B. External Internet:
   Access through the ISP/Internet cloud using NAT/PAT.
This avoids incorrectly calling the internal server room "the Internet."

Correction 4 – IPSec:
IPSec configuration can be feature/version dependent in Packet Tracer.
Therefore, the project will include IPSec as the security design and
demonstrate it on selected representative WAN links if the chosen Packet
Tracer version supports the required commands. The rest of the WAN can
still be demonstrated with routing and ACLs. Do not claim full IPSec
coverage if the simulator does not support it.

Correction 5 – FTP security:
Traditional FTP transmits credentials and data without modern encryption.
For this course simulation, authenticated FTP is acceptable to demonstrate
username/password file access. In the report, explicitly state that
production environments should use SFTP/FTPS or another encrypted file
transfer method.

Correction 6 – Server roles:
The server room will use separate logical server roles:
DNS/DHCP, FTP/File, Mail, Web, NTP/Syslog/Monitoring. This makes
troubleshooting and service demonstrations easier.

Correction 7 – Branch design:
Every branch will use the same standard template. Only the branch number,
LAN subnet and WAN addressing will change. This makes the project
scalable and much easier to troubleshoot.

6. ROUTING DESIGN
================================================================

Primary routing protocol:
OSPF

Suggested:
OSPF Process ID = 10
Area = 0 for the main WAN topology.

Reasons:
- Dynamic route learning
- Automatic route recalculation
- Better scalability than 20-branch static routing
- Easier failure recovery
- Easy troubleshooting with show ip route and show ip ospf neighbor

Core/edge and branch routers advertise only the networks they need.

Useful commands for troubleshooting:
show ip route
show ip ospf neighbor
show ip ospf interface
show ip protocols

IMPORTANT:
Do not rely on static routes for the entire 20-branch network. Static
routes may be used only for special management/default/backup cases.

7. HSRP DESIGN
================================================================

HSRP will be used at HQ between CORE1 and CORE2 for the HQ VLAN
default gateways.

Example VLAN 10:

CORE1:
10.10.10.2/24

CORE2:
10.10.10.3/24

HSRP virtual IP:
10.10.10.1

Example:
CORE1 priority 110
CORE2 priority 100
CORE1 preempt enabled

If CORE1 fails:
CORE2 becomes active.

Repeat the HSRP design for the important HQ VLANs.

HSRP provides:
- First-hop redundancy
- Default gateway availability

HSRP does NOT replace OSPF.
OSPF provides routing.
HSRP provides gateway redundancy.

8. WAN REDUNDANCY
================================================================

The project should have a primary and backup WAN path for important
branches or for the representative branches used in the demonstration.

Example:

BR01
 | \
 |  \
Primary Backup
 |      |
HQ-R1  HQ-R2

OSPF should prefer the primary path through routing cost/metric.
If the primary path disappears, routing should converge toward the
available path.

IMPORTANT:
Do not describe HSRP as the mechanism that detects or repairs a WAN
route failure. That is a routing/WAN function.

For a cost-friendly project, not every branch needs two physically
independent links if the Packet Tracer topology becomes unnecessarily
large. Demonstrate redundancy on critical/representative branches and
document the scalable design for all branches.

21. IPSec / WAN ENCRYPTION
================================================================

Security goal:
Protect sensitive traffic across untrusted WAN infrastructure.

Preferred design:
Site-to-site IPSec VPN between HQ and selected branches, or a
representative branch-to-HQ pair for the Packet Tracer demonstration.

Demonstration:

IMPORTANT:
Packet Tracer feature support varies by version and device model.
Before building all 20 IPSec tunnels, test one tunnel. If the chosen
Packet Tracer image/version does not support the exact IPSec design,
document the intended production design and demonstrate the other
security controls that the simulator supports. Do not build the entire
project around a feature that your simulator cannot execute.

24. TROUBLESHOOTING MODEL
================================================================

Use a strict layered troubleshooting method.

LAYER 1 – Physical:
- Is the cable connected?
- Is the interface up?
- Are ports administratively shut?

Commands:
show ip interface brief
show interfaces

LAYER 2 – Switching:
- Is the correct VLAN assigned?
- Is trunking working?
- Is STP blocking unexpectedly?

Commands:
show vlan brief
show interfaces trunk
show spanning-tree

LAYER 3 – IP:
- Does the PC have the correct IP?
- Is the subnet mask correct?
- Is the default gateway correct?

PC:
ipconfig

LAYER 3 – Routing:
- Is OSPF established?
- Is the destination route present?

Commands:
show ip route
show ip ospf neighbor

LAYER 3 – Gateway redundancy:
- Which HSRP router is active?

Command:
show standby

LAYER 4:
- Is TCP connectivity possible?

Use ping/traceroute and application tests.

APPLICATION:
- DNS working?
- FTP working?
- Mail working?
- Web working?

This layered method makes the source of a failure easy to isolate.

27. COST OPTIMIZATION
================================================================

The design is cost-conscious because:

1. Centralize expensive server resources at HQ.
2. Use standardized low-complexity branch topology.
3. Use VLANs instead of separate physical networks.
4. Use dynamic routing instead of extensive manual routing.
5. Use NAT/PAT to reduce public IP requirements.
6. Use shared centralized DNS/DHCP/file/mail/web services.
7. Use redundant infrastructure only where it provides meaningful
   availability benefits.
8. Avoid unnecessary full-mesh WAN links.
9. Standardize branch equipment and configurations.

Do NOT claim that redundancy is free. Redundancy adds equipment and
links. The design balances reliability with project cost.

31. VIVA EXPLANATION – KEY CONCEPTS
================================================================

Q: Why OSPF?
A: Because there are 20 branches and dynamic routing provides scalable
   route learning and reconvergence after topology changes.

Q: Why HSRP?
A: To provide a redundant default gateway for HQ VLANs.

Q: Does HSRP provide WAN routing?
A: No. OSPF handles routing; HSRP handles first-hop gateway redundancy.

Q: Why VLANs?
A: To logically separate departments, reduce broadcast domains and
   enforce security policies.

Q: Why DHCP?
A: To automatically assign IP configuration and reduce manual errors.

Q: Why DNS?
A: To translate human-readable names into IP addresses.

Q: Why FTP?
A: To demonstrate authenticated file transfer in Packet Tracer.
   Production would use an encrypted file-transfer protocol.

Q: Why NAT/PAT?
A: To allow many private hosts to share public Internet connectivity.

Q: Why ACL?
A: To control which traffic is permitted or denied between network
   segments.

Q: Why SSH?
A: To provide secure remote device administration instead of Telnet.

Q: Why IPSec?
A: To protect sensitive WAN traffic across untrusted infrastructure.

Q: Why NTP?
A: Consistent timestamps are important for logs and troubleshooting.

Q: Why a NOC/Security department?
A: To centralize monitoring, administration, incident investigation and
   network security operations.

================================================================

VLAN + Ethernet + STP

Inter-VLAN:
Layer-3 core switching

OSPF

HSRP

DHCP + DNS + FTP + Mail + HTTP + NTP/Syslog

Security:
ACL + VLAN segmentation + SSH + Port Security + IPSec where supported

Troubleshooting:
Layered diagnosis + show commands + ping + traceroute + application tests

35. FINAL RECOMMENDATION
================================================================

Build the project in stages. Do not configure all 20 branches at the
same time.

First make HQ + BR01 completely functional.

Then make BR02-BR05 functional.

Then replicate the branch template through BR20.

After basic routing works, add services.

After services work, add security.

After security works, add redundancy.

Finally perform deliberate failure tests.

The project should be judged not by the number of devices alone, but by
whether every technology has a clear purpose and can be demonstrated.

The final design is therefore:
- Professional
- Scalable
- Cost-conscious
- Redundant
- Secure
- Service-oriented
- Easy to troubleshoot
- Appropriate for a Computer Networks course
- Practical to implement in Cisco Packet Tracer
